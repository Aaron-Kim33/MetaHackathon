# Mobile editor conventions

- Every new or changed user-facing message must support Korean and English together. Add the Korean source key and reviewed English wording in `src/translations.ts`. Use `t()` for labels, accessibility text, placeholders, alerts and errors, and `LocalizedText` for native text. Never translate user input or model prompts automatically.
- The editor follows the device language initially (Korean for ko, English otherwise). Explicit language selection is saved separately from projects. Language changes must preserve the current editing session.
- Keep English text readable in the existing full-canvas mobile layout. Allow wrapping where necessary instead of shrinking the editing canvas.
- Respect the user's request to conserve credits and verification effort: never increase model call caps or make live AI calls without explicit approval of the scope/count. Do not automatically retry uncertain requests. Do not operate or record the user's phone unless asked.
- Archive every future AI experiment in `.local/ai-tests/` using `recordedModelFetch` from `server/experiment-log.mjs` (or the existing Meta adapter, which wraps live fetch automatically). Do not send ad-hoc live requests through bare `fetch`. Pass the approved scope/count in `context.approval` for experiments. Injected mock requests must be marked `simulation:true` and use an isolated temporary root.
- Record exact prompts and settings, immutable before/after image snapshots, model/request ID, client duration and its measurement scope, status (including no-match/failure), reported usage, dated pricing source, estimated cost and separately verified Billing charges. Never invent missing measurements. Add a visual assessment after reviewing outputs, distinguish local corrections from model results, and never infer numerical accuracy without reference masks. Add final output PNGs with `addTestOutput`. Reports update automatically; `npm run ai:log` rebuilds them without network/model calls.
- Keep experiment images and raw responses private in the ignored `.local/` directory. Never publish participant photos or keys as part of the public hackathon repository. Do not log Authorization headers, API keys or connection codes.
- Product requirement: AI results are reusable assets, not disposable outputs. Preserve original photos, cutout masks, repaired versions and generated decorations with provenance. Allow reuse across edits without another model call. Check for an identical source + model + prompt + settings result before making a new request, and distinguish reuse from new inference in logs. Moving, resizing, rotating, changing themes, undoing and reopening must not trigger inference. A failed downstream step must retain successful earlier outputs so only the missing step needs execution. Explicit regeneration is a separate action, never an automatic retry.
- Reusable AI assets are separate from project history: keep the user's existing preference to restore only the last editing project, rather than showing a gallery of recent projects.
- User explicitly removed the proposed pre-execution cost confirmation screen from the product flow. Do not add a per-action cost approval modal. Keep cost/usage recording, call caps and the existing development-test approval requirement; this UI decision does not authorize unlimited experiments or higher caps.
